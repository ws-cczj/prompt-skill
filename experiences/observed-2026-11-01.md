# 历史会话首批观察：2026-11-01

来源：授权目录下的40个活跃或归档会话。具体本地会话与回合索引保存在被 Git 忽略的 `evaluations/2026-11-01/`。以下只保留去标识化的必要规则；记录为“已观察”表示会话中存在相应纠正，不代表对策经过独立生成复测。没有重新打开历史产物验证全部用户报告。

## E009：任务动作与生命周期混淆

- 状态：已观察；对策待验证。
- 证据：R01、R02。用户明确“创建一个skill”，历史回复承认混淆创建期参考材料与安装后输入，并承认擅自生成过仿写文件。
- 对策：prompt 先确定动作是诊断、修改技能、生成产物、教学还是只讨论；再区分创建期、使用期与维护期。创建期范例不自动成为每次运行的必填输入。
- 边界：用户明确同时要求示范生成时可以生成；不能用此经验禁止所有示范。

## E010：同一材料不同角色与不同学习维度

- 状态：已观察；对策待验证。
- 证据：R04、R10。用户强调“项目书是内容，师兄师姐是模板”，以及公众号只学习内容、不学习格式；前一纠正在长会话中再次出现。
- 对策：在相关输入中记录“材料 → 用途 → 不采用维度”，必要时分别维护事实来源、内容组织来源、排版来源。不能把一份附件整体提升为所有维度的规范。
- 边界：没有明确分工时保留假设，关键分歧才询问，不要求每个普通附件都填表。

## E011：数量限定和操作范围被改写

- 状态：已观察；对策待验证。
- 证据：R03。用户多次纠正“至少五条”并非“固定六条”；另有文献检索请求明确主题可以组合、不必全部满足。
- 对策：保留至少、至多、恰好、约、可选、除非、同时/任一等逻辑词。验收按原关系检查，不能为填满模板编造结果。
- 边界：仅保留该任务给出的数值，不把至少五条扩展为所有总结的统一标准。

## E012：局部修订丢失保留项

- 状态：已观察；对策待验证。
- 证据：R06–R09。删除旧定位的表述时用户明确不删除格式；目录先改名后又改根目录入口；同回合末撤回了顺序调整。
- 对策：维护变更集：新增、替换、撤销、明确保留。新规则逐属性替换，格式等无关要求保留；同回合追加消息按实际到达顺序更新。
- 边界：复述确认只在用户要求或实质冲突无法消解时使用，不对所有修订增加确认环节。

## E013：工具与能力条件作用域错误

- 状态：已观察；对策待验证。
- 证据：R05、R13。本机 Git CLI 被误解为技能运行依赖；其他会话明确禁止 computer-use。
- 对策：区分当前维护工具、最终使用者依赖、用户禁止工具与尚未确认的能力。不能把 SSH 到服务器等同于操作终端客户端，也不能用另一界面工具绕过禁止项。
- 边界：工具不足导致目标无法完成时，说明具体能力缺口；经验不能凭空赋予替代操作授权。

## E014：视觉生成只检查外观或文件成功

- 状态：已观察（用户多次报告）；对策待验证。
- 证据：R11 及对应后续纠正。用户指出双键、O连接端点、箭头、温度曲线和分页布局含义未被正确表达。本次未重新查看原图，因此不独立判定每处结构错误。
- 对策：对于承载科学或流程意义的图，先列对象、关系、阶段和标签含义，再绘制；实际查看最终产物，对语义和视觉分别检查。避免把没有报错当成图正确。
- 边界：普通风景图无需做化学结构核查；科学关系未知时需查证，不能仅按用户猜测补画确定机制。

## E015：记忆和完成声明被当成独立证据

- 状态：已观察（用户报告）；对策待验证。
- 证据：某轮用户指出铺层符号在成稿和 memory 中同时错误；多会话仅有历史 assistant 的完成声明，没有新的独立验证。
- 对策：记忆保留来源与核验状态。发现矛盾时返回原始证据，而不是用旧 memory 证明自身；区分用户反馈、旧 agent 声称、本次观察和独立复测。
- 边界：不要求每次全量重读；依据变化或具体风险针对性复核。用户表达失望本身不是事实错误或失败根因的证据。
