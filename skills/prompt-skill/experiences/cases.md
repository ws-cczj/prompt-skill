# 初始场景与检查对策

以下记录于 2026-10-31，来源为用户对 skill 目标的说明及据此构造的检查用例。全部为待验证场景，不代表已发生或已修复的测试失败。

## E001：学术 PPT 的交付物被弱化

- 状态：待验证。
- 场景：用户要求“根据这篇论文给我生成一个学术 PPT”。
- 风险假设：只给提纲或泛用模板，忽略论文、受众或此前的汇报限制。
- 对策：明确实际演示文稿这一交付物，检查论文是否可访问，并提取相关历史中的受众、时长、语言及版式限制。未提供页数时不得假称用户要求固定页数。
- 复测输入：前文“中文组会，十分钟，不要动画”；本轮“根据这篇论文生成学术 PPT”。
- 预期：prompt 保留全部四项条件，关联论文输入；时长不等于页数。缺论文时只追问材料或检查可访问的附件。
- 实际结果：尚未执行行为复测。

## E002：风景图片只得到生图说明

- 状态：待验证。
- 场景：用户要求“给我生成一张风景图片”。
- 风险假设：把执行 prompt 或图片描述当成最终图片，或默默添加强制风格。
- 对策：prompt 中明确产物为一张图片。风格、比例等未指定且不阻塞时可以选择可调整默认值，不标为用户约束。执行时使用实际可用的生图能力；用户只要提示词时才以文本为最终产物。
- 复测输入：前文“不要人物和文字”；本轮“生成一张风景图片”。
- 预期：prompt 保留一张、风景、无人物、无文字；执行交付图片。用户说“只写提示词”时不调用生图。
- 实际结果：尚未执行行为复测。

## E003：分散在前文的限制丢失

- 状态：待验证。
- 场景：约束与任务动作不在同一条消息中。
- 风险假设：只读最近一句，或忽略“不要”“只依据”等否定和来源限制。
- 对策：在当前任务范围内建立有效约束清单，逐项对照最终 prompt；无法取回的历史信息明确说明，不假称已恢复。
- 复测输入：“只依据我给的材料，不要补实验数据”；随后“把结果做成汇报”。
- 预期：prompt 保留来源限制与禁止编造数据，不能为了完整性虚构结果。
- 实际结果：尚未执行行为复测。

## E004：新修订误删未变的要求

- 状态：待验证。
- 场景：用户只调整原任务的一个属性。
- 风险假设：所有旧要求全部失效，或旧偏好继续覆盖最新修订。
- 对策：按属性更新；新值替换同一属性的旧值，其余适用约束保留。无法兼容的并列要求标为冲突。
- 复测输入：“中文，八页，蓝色，不要动画”；随后“改成十二页，颜色改暖色”。
- 预期：最终为中文、十二页、暖色、无动画；八页和蓝色不再作为有效约束。
- 实际结果：尚未执行行为复测。

## E005：无关任务继承旧偏好

- 状态：待验证。
- 场景：从汇报制作切换到独立的图片生成。
- 风险假设：把任务级偏好永久化，或把经验示例中的规格应用到所有任务。
- 对策：判断约束作用域。明确长期偏好才跨任务继承；只有措辞不清且会影响结果时询问。
- 复测输入：“这份 PPT 用蓝色，十六比九”；完成后“另做一张正方形的秋日山景图”。
- 预期：图片使用明确要求的正方形，不继承 PPT 的蓝色和十六比九。每轮展示 prompt 的会话测试约定继续有效。
- 实际结果：尚未执行行为复测。
