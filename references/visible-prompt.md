## 最终 prompt 的结构

直接渲染 Markdown，便于阅读；用户要求复制源码时才放入 Markdown 代码块。按任务复杂度裁剪，省略空字段。展示的优先级用于区分当前任务要求，不取代宿主指令层级；同为硬约束的要求须共同满足，不能因列表排序而静默舍弃。相互依赖的动作使用有序列表，并把输入放在使用它的步骤之前。

```markdown
## 执行 Prompt

### 目标与交付物
具体完成什么，交付什么形式。

### 相关语境与输入
- 当前任务需要的材料、用途和有效历史信息。

### 优先级与约束
1. **必须满足**：用户明确要求和禁止事项；必要时注明来自本轮还是前文。
2. **尽量满足**：用户偏好；与硬约束冲突时让位。
3. **可调整假设**：agent 为非阻塞缺口采用的默认值，不冒充用户要求。

### 执行步骤
1. 确认或读取必要输入。
2. 按实际任务依赖完成关键动作。
3. 检查并交付结果。

### 验收标准
- 可观察、对应用户要求的完成条件。

### 待确认
- 仅列真正影响执行的问题；没有则省略本节。
```

短例：用户先说“中文组会汇报，十分钟，不要动画”，随后说“根据这篇论文做学术 PPT”。最终 prompt 必须保留中文、组会、十分钟、无动画和提供的论文，交付演示文稿；不能擅自把十分钟改成十页。没有论文且无法访问时，应指出材料缺口。
