# Agent 规则同步

## 选择作用域

| 信息 | 保存位置 | 生效边界 |
| --- | --- | --- |
| 明确适用于整个项目的持续规则 | 项目根目录 `AGENTS.md` 的受管区域 | 当前项目 |
| 明确只针对子目录的规则 | 检查现有规则层级后，更新对应目录的规则文件 | 对应目录 |
| 普通对话、仅限本会话的持续约定 | 宿主提供的会话规则接口；没有则使用下述隔离快照 | 指定会话 |
| 单次任务输入、交付参数与未完成状态 | 会话快照中的任务检查点 | 当前任务，完成即归档或清理 |
| 推测、临时默认值、经验建议 | prompt 的假设栏或经验库 | 不自动成为规则 |

用户明确指明范围时以该范围为准。在项目里明确启用的“本项目每轮展示 prompt”等规则可以维护到项目入口；“这张图不要人物”等单次约束不能扩散。范围不明时采用当前任务或会话这一较窄范围，并标明范围；确实影响执行且无法判定时只暂停有争议的规则变更，按拦截流程澄清。普通对话不得仅为持久化任务约束而写入用户全局 `~/.codex/AGENTS.md`；用户明确授权主机级安装或调整时，可以仅维护获授权的全局入口，仍不将项目内容或会话私有规则写入全局。

## 项目文件的合并

写前读取已有内容及适用的上层、覆盖文件和目录规则，不覆盖他人维护的段落。优先维护已有的 prompt-skill 区域；新区域可用 `<!-- prompt-skill:rules:start -->` 与 `<!-- prompt-skill:rules:end -->` 标记。不要为了覆盖现有规则而另建 `AGENTS.override.md`。若现有有效入口是 override 文件，确认其实际优先级，在有效入口同步相应内容，避免修改被忽略的文件。

项目规则使用稳定 ID 和简短来源，保留当前有效版本；删除或替换时记录简短变更摘要即可，不把全量聊天或每轮日志塞进入口。无规则变化时不重写文件。

## 会话规则快照的回退方式

当前没有确认可用的专用会话规则写入接口时，将快照写到：

```text
<CODEX_HOME 或 ~/.codex>/prompt-skill/sessions/<真实会话 ID>/AGENTS.md
```

该路径是本技能的本地约定，不是宿主内置的自动发现机制。项目入口或已加载的技能应指示 agent 显式读取当前会话的快照。不能承诺未加载本技能的普通聊天也会自动恢复。

使用宿主实际提供的当前会话 ID，例如已存在的 `CODEX_THREAD_ID`；同一聊天跨轮保持相同 ID。不能根据标题、工作目录或“最近的会话”猜测身份，不使用多个会话共享的 `current/AGENTS.md`。新会话默认不继承旧会话记录；用户明确要求继承时复制适用规则并保留来源。无可靠 ID 时可建立独立记录并报告恢复路径，但不能声称已自动绑定会话。

写前只读取匹配会话的现有快照并合并，不枚举或导入其他会话内容。普通对话快照保存在仓库外，避免进入版本控制；记录最小必要内容，不存凭据、全量私密聊天或无关个人信息。保持已有文件权限；不得将无效或外部传入的 ID 用作任意路径片段。

## 每轮同步与恢复

1. **恢复**：确认当前项目、会话身份，读取适用项目规则与该会话快照。验证会话 ID、作用域和任务状态匹配，忽略其他会话的规则。若未读取成功，不能声称已经恢复。
2. **提取增量**：从本轮明确要求中提取新增、修改、撤销；当前用户的明确修订优先于记录的旧版本，同时遵守宿主指令层级。需要纠正已有记录时按属性修改，不抹掉无关要求。
3. **去重与消冲突**：同义要求合并；已替代的规则退出有效清单。不同范围的规则不要简单拼接成更高权限。未解决分歧记入待确认，不让规则文件把分歧“固化”。
4. **持久化**：只在有实际变化时更新对应记录。每条持续规则包含稳定 ID、规则、范围、状态、来源及必要的替代关系。假设只记录在任务状态中。
5. **检查一致性**：最终 prompt 与持久规则一致；项目记录不包含会话私有输入；撤销项不再生效；完整保留受管区域外内容。简短报告实际变更，不能以规则写入替代原任务。
6. **更新检查点**：任务发生实质变化或准备交接时，维护目标、已完成、下一步、有效任务限制、待确认项及必要的产物路径。完成后移除过期任务限制，保留明确的持续约定。

可以使用 Markdown 表格记录规则：`ID | 规则 | 作用域 | 状态 | 来源`。来源使用简短原话或可定位的消息标记，不编造消息 ID。有效清单保持精简，历史仅保留必要变更摘要。不要写入内部推理。

## 行为复测要点

- 项目规则与会话规则分别变更时，另一作用域不受污染。
- 两个会话具有相同任务标题或工作目录时，不能读取对方记录。
- 用户只改页数时保留其余要求；撤销展示模式后停止展示。
- 规则同步后模拟上下文恢复，检查能否保留有效约束和下一步。
- 已有 AGENTS 文件的其他段落保持原样；不创建无效或意外覆盖的规则入口。

以上是复测要求，编写这些要求不代表已经通过行为测试。

## 宿主发现机制依据

Codex 官方说明项目规则按目录层级发现，且存在覆盖文件、读取时机和体积限制。本技能采用显式恢复以应对运行中的更新，不依赖文件写入后立即自动重新注入。参见 [OpenAI Docs：Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。会话快照目录是本项目设计，不应描述成官方会话规则功能。
